## 完整性依据

原始输入仍使用[第一轮审计](crsa-display-gaps-20260903.md)的六字节 CRsa 前缀
扫描和严格分块校验。每个明文缓存必须与扫描 census 的块集合、长度和哈希一致。
本轮末尾重新计算六个当前 RIO 文件的完整 SHA-256，均与该输入一致；两份游戏
EXE 也与字段描述符来源一致。当前 PF RUO 是 24 路，其中 22 个 CRsa；PM 无 RUO。

`crsa_vm_stream.py` 从 24 字节头顺序读取所有命令，维护共享类 / 对象缓存，
按 EXE 中的原生类型描述符解释通用操作，再读取池长度、全部池单元、尾部引用
和全零填充。它不依靠可读字符串搜索重新同步；未知类、版本、字段类型、越界
读取或未解析的非零尾部均失败，不能返回“完整”。

全部 466 个原始记录、22 个当前覆盖记录均读到末尾。原始记录中的 3,506 个
外部 CRsa 引用记录全部能定位到六卷扫描结果，没有漏在调用图之外的已引用
CRsa。原生解析找到的 58,011 个消息边界与修正后的消息提取器逐个一致。

覆盖了 Call / Jump / Label / Ret / Msg3 / GenericMsg / FlagOp / Sync /
Sound / DirectionSync / Blt；通用操作中的 CString、调用参数、变量绑定、
内嵌姿态和运动曲线、共享缓存的 MFC 曲线对象、特效及模型缓冲区都有明确边界。
CString 读取同时支持 ANSI 与 Unicode；本批真实 CString 全为 Unicode。

每个消息每种语言的三个字段均入账：正文、批注、指令。本批非零辅助引用共
265 个，都是批注；第三字段均为空。文本池中的全部非空单元最终属于消息、
找回的批注或单独列出的 767 段未引用旧尾文。纯空白与控制字段同样有记录。

## 批注字段与已排除的兵装名参数

兵装名存在于 `CVmCall` 参数 2。四个被调用脚本分别为：

| 游戏 | 被调脚本 raw key | 绑定 |
| --- | --- | --- |
| PF | `0xC634C9DC`、`0xC634F69E` | 参数 2 → `OM_TWF_SetArm.兵装名` |
| PM | `0xF9367126`、`0xF936A58F` | 参数 2 → `OM_TWF_SetArm.兵装名` |

这些绑定均以 `_CString` 变量、序号 2、成员偏移 12 指向
`CTWFRemainderBox`。PF 原生处理函数 `0x4612E0` 将该成员复制到兵装名称字段。
这确立了兵装名参数的静态用途。按维护者此次确认的范围，260 处全部保留原始
字节，并排除漏译统计和补丁操作；保留这些结构证据用于验证没有误改参数。
静态绑定证据不等于逐个出现位置都已经实机触发。

批注位于 `CVmMsg3.first_records[language][1]`。PF 的消息执行逻辑从
`0x4BD388` 读取该索引，并进入 `0x4B3080` 的批注处理路径；第三字段另有用途。
过去只重建正文索引的处理遗漏了这些字段。

当前有效数据中，263 / 265 个批注的原索引与找回的批注单元不一致；
显示列 20 个全部如此。每项同时保留原索引、原索引实际指向的文本、相邻布局
得到的批注位置和键在正文中的匹配结果。相邻恢复不冒充有效原生引用；若有效
引用与相邻批注相互冲突，读取器报告冲突并保留未归属单元。

部分键仍是旧外文片段，而正文已经改写。因此后续需分别审校释义、标注对象和
索引；不能机械地往正文插入全部批注，也不能仅替换批注中的英文。

## 排除误报与保护原审校身份

旧 85 个待确认项全部归类：20 个批注、13 个已经被消息引用的正文单元、
51 段旧尾文、1 个有真实 CString 归属的标题字段。完整的未引用尾文实际为
767 段，集中在 PM `.004@655753292`；它们均单独导出，不重复插入对白。

旧宽松扫描共 107,167 个未归属探测命中（其中当时标为 pending 的为 105,987），
现在全部落在已解释的头、命令、文本池、尾部或跨结构区间内。PM 的 35 个
“可解析 CString 标记”并不是真实 CString，实际位于其他类型字段中；15 个
无效标记也明确归属。原生字段计数因此与宽松标记计数不同。

同时修正了跨 NUL 借用后续正文身份的问题：空源 / 控制源槽以其原生索引结束，
只保留已证实的 U+0010 前缀规范化。PM 六个控制命令不再冒认紧随其后的对白；
池索引 0 的空源也不再借用第一句。原文内容、原稳定 ID 和译文均未改动。

六份旧审校 CSV 的 57,547 条记录全部通过“同块内、真实源字段、源文哈希”的
对应检查，文件哈希前后相同。新字段使用独立审计定位标识，不以偏移巧合覆盖
旧 stable ID。43 项合成数据回归测试通过，包含旧提取 / 构建器回归，以及失败重跑
不得遗留旧“完整”报告的检查。
