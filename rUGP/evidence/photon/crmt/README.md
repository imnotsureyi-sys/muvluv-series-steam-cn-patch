| 有独立英文本地化 | 23 | 官方日文与官方英文明确对应 |

处理方式为中文改图 38 组、用户成图 1 组、translation 槽复用日文官图 3 组、保留日文官图 7 组。
分类包括日期地点、人物姓名、招式标题、BETA 资料、地图、技术状态警告、武器、招牌和保留官图的界面。

`review-catalog.json` 逐条保存：

- 官方对象的游戏、分卷文件名、偏移、长度、整记录 SHA-256、ImageMP 引用及每层尺寸／像素哈希；
- 日英对应关系；`official_english: null` 明确表示无独立英文本地化；
- 当前中文文案、处理决定、中文稿与实际编码记录的哈希、每层回读 PNG 哈希；
- 视觉审核、编码检查与受控实机证据的不同状态。

“官方日文”指日版实际使用的原图，图内本来可以含英文。不能只看图中文字语言判断槽位。
同样的图片出现在两个物理对象时不能合并掉写入目标。三列的层数与尺寸不同也不人为补齐。

## 验证状态的边界

本次公开清单逐条汇入最近一批 **17 组／18 个记录／91 个 mip payload** 的
原始目标键专用入口显示证据。中文记录与候选稿、截图、只读探针报告的哈希都经导出器核对。
这证明该诊断环境请求正确目标后能显示对应图，并匹配各层压缩 payload；
不表示每个缩放层都被单独绘制，也不是所有原剧情的时机、遮挡、坐标和最终发布包验收。

其余记录标记 `not_imported_in_this_snapshot`，意思是旧批次运行证据未汇入这一结构，
**不是“失败”或“从未测试”**。截图与完整原始报告不随此仓库分发，公开哈希是身份绑定，
不能代替读者自行实机验证。该清单不能直接充当自动发布白名单。

后续 PM 修正运行时的 7 个记录／37 层、两次冷启动及正式 Steam 启动检查见
[运行验证摘要](runtime-summary.json)。它与上述诊断证据分开，不把一次正常剧情启动算成全图实机通过。

## 历史数字不要混用

早期“56＋811＝867”是当时的严格解码与文字审核子集；后来的 20,650 是去重后的主要图片清单；
当前 49 则是按阅读理解及用户决定整理的汉化审核组。三者不是相互矛盾的全量计数。
本 PR 不复制旧阶段所有 JSON 和试验脚本，也不把旧“待审核”状态覆盖当前用户已批准的视觉稿。

公开目录中的合成测试能验证编解码器与边界检查，但真实游戏结构普查、图像审核和实机仍需要
匹配版本的个人游戏副本。当前清单中的 90 个官方对象都没有外部图片成员；这是该子集的事实，
不能推广为所有 CRmt 都没有外部 CRmti。
