# 04 · 章节术语工作流

[规则顺序](README.md) · 上一步：[03 表字段](03-table-schemas.md) · 下一步：[05 初译](05-translation.md)

本文规定每个游戏或章节开始前和翻译过程中的术语确认、冻结与同步方式。目标是在当前范围内保持一致，并把可复用的确认术语沉淀到对应目标语言的公共术语表。

## 1. 文件和角色

- 当前简体中文公共表：[`../glossaries/muv-luv.ja-zh-Hans.csv`](../glossaries/muv-luv.ja-zh-Hans.csv)
- 生效表使用 `jp,cn,context` 三列；新语言必须新建独立文件和目标列，不能覆盖简体中文表。
- 每作仅加载公共表和本作 `project.toml` 指定的专表；TDA00、01、02、03、帝都燃烧、PF、PM 互不继承专表。入口和历史边界见[术语目录](../glossaries/README.md)。
- 拟声片段、普通词和句子片段不是强制术语。`context` 的人物/机型/完整说话人限制必须遵守，严禁对正文进行无语境的批量替换。
- 公共表只保留稳定术语对；理由、状态、来源和审核讨论保存在候选记录或 pull request 中。
- 本作公开基线由 project.toml 的 terminology_baseline 指定，保存候选、理由、来源行号、原状态和篇章范围；完整官方例句留在本地，不随基线公开。
- 术语表与基线必须分开计数；旧表的来源记录不得仅因未命中筛选而消失。候选、语境限定与确认不能互相冒充。
- 仓库维护者负责公共表、跨游戏协调和最终同步。
- 单个章节的变更只处理本章术语，不直接修改其他章节正文。

## 2. 哪些内容属于术语

应优先扫描：

- 人名、姓氏、昵称和称号。
- 国家、组织、部队、机构和派系。
- 军衔、职务和固定称谓。
- 机体、兵器、装备、设施和技术名词。
- 作战名、计划名、地名和事件名。
- 有命名感的固定表达、反复短语和作品内梗。
- 重要カタカナ词、外语词和缩写。

普通动词、形容词和只出现一次的日常表达通常不进入总术语表。

## 3. 章节开工前的全章扫描

正文初译开始前，先在合法本机源数据中扫描本章全部 JP 文本：

1. 提取候选术语及其出现次数和典型上下文。
2. 与公共总表逐项比对。
3. 分类为：
   - `confirmed`：总表已有且适用于本章。
   - `candidate`：总表没有，需要确认译法。
   - `contextual`：同一 JP 可能因语境采用不同中文，需要记录适用条件。
   - `question`：含义、指代或固定写法仍不确定。
4. 对高频、关键剧情和跨章节术语优先确认。
5. 形成“本章术语基线”，记录日期或版本，随后才开始批量初译。

章节开工时要确认的是专名和固定表达，不需要让维护者或审校者逐个审批普通词句。

## 4. 译法确认依据

译法判断顺序：

1. 本章已冻结基线和当前目标语言公共表中已经合并、且适用于该语境的译法。
2. 作品内 JP 上下文和官方日文设定。
3. 已有可靠中文惯用译名或经确认采用的中文资料。
4. 在语义明确的前提下，根据人名、专名、称号等类别决定音译、意译或保留英文。

其中第 3、4 项描述当前简体中文目标；其他语言应换成对应语言的可靠资料和专名规则。英文槽、旧译文和模糊匹配不能作为原文含义的最终依据。网络资料只能作为可审查证据，不能越过 JP 原文和已经合并的项目决定。

## 5. 翻译中的术语处理

1. 每批开始前检查本批术语是否都在本章基线中。
2. 新出现的专名先加入章节候选记录，不能在不同批次随意采用不同译法。
3. 拿不准时标记 `question`，不得硬猜或静默替换。
4. 已冻结术语若需修改，必须记录旧译、新译、原因和影响范围。
5. 修改跨章节公共术语前，由维护者检查 TDA00-03、帝都燃烧篇、Photon 及其他受影响范围。
6. 术语变更后应重新检查本章所有出现位置，不能只改当前一句。

## 6. 冻结和版本更新

“冻结”表示当前章节按这版术语推进，并不表示永远不能修改。

需要更新基线时：

1. 先确认新译法。
2. 记录受影响的 JP 词条和章节范围。
3. 更新章节术语基线版本。
4. 扫描本章所有旧译变体。
5. 若属于可复用专名，再由维护者同步到对应目标语言的公共总表。

不得在没有记录的情况下直接覆盖已确认术语。

## 7. 同步公共总表

满足以下条件的词条可以进入公共总表：

1. JP 和目标语言对应明确。
2. 译法已经确认。
3. 具有跨场景或跨章节复用价值。
4. 不依赖只在某一句成立的临时语境。

简体中文表同步时写 `jp,cn,context`，使用限制写在 `context`；详细来源、争议和审定理由留在候选记录、审计记录或 pull request 中。旧混合表与待确认项不参与加载。新语言使用自己的文件与目标列。

## 8. 章节术语完成标准

章节进入最终审核前，应满足：

1. 高频和关键专名都有明确译法或仍在可见的 `question` 清单中。
2. 同一术语没有无依据的多种目标语言变体。
3. 称谓差异可以由人物关系和场景解释。
4. 本章新增的可复用术语已提交维护者确认。
5. 公共总表与章节最终采用译法没有未说明的冲突。
